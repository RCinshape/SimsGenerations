# family engine contract

`family-engine.js` exports `FamilyEngine.normalize({owner, family, sync, edits})` in a browser, node, or apps script. it returns `sims` keyed by exact string id and a deduplicated `edges` array. parent edges point from parent `a` to child `b`; other links are unordered. a complete observed child parent list is authoritative over conflicting inverse parent children lists; suppressed claims remain listed as `parent_conflict` issues. partial and unknown scans do not erase historical facts. when a later incomplete inverse claim conflicts with a prior complete child observation, it remains an unresolved issue rather than an inferred parent. `childCount` counts direct biological, adoptive and unknown-role links, excluding guardians and pets. `children` includes guardian links so callers must use `childCount` for the count. placeholders have `missing: true`; edits appear in `edited`. game observations and manual overlays remain separate.

legacy storage is owner-scoped, not save-scoped. `scope` therefore says `legacy-owner-unverified-save`, and `partial` is true. records are unioned by the existing backend and sync records are ordered by server receipt, not verified capture order. omission is never treated as removal. the engine isolates imported cycles and lists them in `issues`; raw records remain untouched. legacy family files are already projections, not immutable capture history. save lineage, rollback detection, stale upload rejection, complete-scope reconciliation and preservation of contradictory historical claims are not established by this adapter.

`family_read` accepts `{owner}` and returns `scope`, `captureState`, and `canEdit`; `family_edit` accepts `{owner, scope, revision, op}`. edits require the same bound scope observed by the reader. an unbound scope returns 409 `scope_unbound`, and an outdated scope token returns 409 `scope_conflict`. `family_capture_state` reads available sources; `family_capture_bind` accepts `{owner, revision, streamId}` and requires owner authorization. scope binding never establishes that the stream is a unique save lineage. legacy and each collector stream use distinct edit files. both return `{graph, revision, edits}` on success. edits require the authenticated owner, use the existing roster/tester visibility fence, execute under the script lock, and compare revision; conflicts return 409 `family_conflict`. editing does not change the game. supported operations:

- `{type:'add_sim',id,fields}` creates a unique `manual-` id of at most 40 characters.
- `{type:'set_fields',id,fields}` and `{type:'reset_fields',id,fields:[...]}` set or clear individual overrides. allowed fields are first, last, age, gender, dead, occ, kind, traits, aspiration, skills, career, notes and hidden.
- `{type:'remove_sim',id}` removes a manual record and its edited links. hide imported records with `hidden` instead. `undo` restores the previous edit state (up to ten states).
- `{type:'add_link',a,b,linkType,role,status}` adds a parent, partner or friend link. parent roles are biological, adoptive, guardian or unknown; partner statuses are married, dating, separated, widowed or unknown. `{type:'remove_link',a,b,linkType}` stores an exclusion; `{type:'reset_link',a,b,linkType}` removes it and resumes the game observation.

`{type:'link_manual',id,targetId,portraitChoice?}` merges a manual sim into an existing imported sim within the selected owner scope. it transfers fields and links. in each bound scope, an owner-scoped portrait alias retains a source-only portrait without copying its file; undo restores the previous alias state. when two portraits differ, the request returns 409 `merge_conflict` with `part:'portrait'`; the owner may retry with `portraitChoice:'manual'` or `'game'`. conflicting fields and links also return `merge_conflict`. a later target portrait write supersedes its alias. removing an aliased portrait requires the revision-checked `{type:'clear_portrait_alias',id}` edit first. existing portrait files are untouched by merge and undo. portrait list/get/put/remove require the selected `scope`. each stream has an isolated image, index, and version clock namespace; legacy filenames remain unchanged. unbound and stale selections return 409 `scope_unbound` or `scope_conflict`.

`family_audit` takes an empty body and returns a read-only aggregate per visible roster member: sim, edge and issue counts; scope and partial state; capture metadata; receipt time; and edit revision. it never backfills or rewrites records and follows the same tester fence. counts reflect existing projections and do not establish real-world correctness.

build a private candidate with `node scripts/build-family-backend.cjs INPUT.gs OUTPUT.gs`; the input and output must differ. the builder inserts three routes, the shared module, edit and portrait-alias modules, and narrowly checked portrait integration changes. it fails if markers are missing or duplicated and syntax-checks the result. apply the capture and source patch before this builder, then test the combined candidate against a copy of production data. never commit a private backend bundle. run `node --test tests/family-engine-v2.test.cjs` for the shared semantics and backend authorization/revision checks.
